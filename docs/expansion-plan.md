# 任务与场景拓展规划

## 推进方式

先横向覆盖不同交互类别，再围绕各类典型任务纵向拓展，最后组合成多步任务。一个典型任务跑通后，立即做少量变体验证实现没有依赖单一对象或固定布局，再进入下一类。

任务数量与交互能力分开看：更换对象、容器或目标位置属于变体；推移、工具接触、双臂交接等带来新的交互要求。参考本地 `sim_projects` 中 RoboDojo、RoboTwin、ManiSkill 和 RLBench 的任务组织，按实际动作与成功判据选择典型案例，不只依据任务名称。

## 当前进展

积木的七个方向／距离／选择案例保留为回归验证，不再作为主要任务拓展。当前推进真实日常物体：把浅盘推到有碰撞的薄餐垫上，把打开的纸盒推入可见收纳标线；引入完整物体进入区域与防倾倒判据，并按物体几何适配接触高度。资产、实际效果与失败边界统一见[日常物体推动](implementation.md#日常物体推动盘子与纸盒)。

保持动作简单，不扩展复杂朝向控制或绕障。后续新增任务应带来新的物体／场景语义或接触要求，参数扫范围作为回归，不以配置数量衡量任务进展。

## 建议顺序

现有抓起、放入作为基础与回归案例。以下为拟新增任务，具体资产和验收容差在各项开始前确认。

| 阶段 | 类别典型 | 主要新增能力 | 后续少量变体 |
| --- | --- | --- | --- |
| 第一阶段① | 盘子归位、纸盒整理 | 真实物体接触适配、可见区域、完整包含与防倾倒 | 布局、干扰物与指定区域选择 |
| 第一阶段② | 双臂交接物体 | 两臂时序、接收抓持、递出释放与避碰 | 物体、交接位置、交接方向 |
| 第一阶段③ | 持工具扫物体入区域 | 工具抓持、作用点与连续接触 | 待扫物数量、分布、目标区域 |
| 第二阶段① | 打开／关闭抽屉 | 关节物体、约束运动、状态记录与重放 | 开合方向、目标行程、安装位置 |
| 第二阶段② | 插销入孔 | 几何对齐、插入与卡住诊断 | 初始偏差、目标位置、配对几何 |

第一阶段优先复用已接入刚体资产和双臂部署，从盘子／纸盒整理推进，积木保留为回归；工具需先筛选验证。第二阶段待第一阶段效果确认后推进，抽屉与插销配对资产需另行准备。缓存模型不等于可用任务资产，接入遵循[资产质量门槛](scene-assets.md#质量门槛)。

## 场景如何拓展

场景随交互需要逐步增加：通用桌面用于抓放与推移，双臂共享工作区用于交接，工具操作桌面用于扫动，机构／装配工作台分别加载抽屉或插孔夹具。尽量共享桌面和已有资产；对象款式、布局采样、干扰物和可达范围作为场景变体管理。

先固定 Panda 部署；交接使用其双臂。每类完成典型案例及少量对象／布局变化后，再选择代表案例切换本体，不做全部任务、场景和本体的笛卡尔积。

## 每项如何完成

1. **确认定义与资产。** 查看尺寸、碰撞和功能部位，明确动作过程、成功条件及不可接受的捷径；资产或物理表示的关键选择先讨论。
2. **验收最小案例。** 固定初态跑通完整物理过程，给出视频和测量。例如推移需检查是否被抬起搬运；交接需验证接收抓持后递出释放；插入需排除穿透导致的假成功。
3. **验证少量变体。** 先用少量固定种子检查位置与朝向变化，再增加对象或布局。保留失败，区分初始化、规划、接触执行和判定问题。
4. **整理可复现入口。** 同步配置、采集与重放命令、结果路径、判据和已知限制；以实际效果和数据完整性验收，不以单元测试或规划成功代替。运行说明集中维护在[运行指南](implementation.md)。

实现按任务需要补齐专家、判据和物理状态；发现职责耦合时随案例修正，不把通用架构重构作为拓展前置条件。继续遵循现有不以低速度作为任务成功门槛的约定。

## 后续组合

典型任务及变体验证后，再组合“开抽屉 → 放入物体 → 关抽屉”等多步任务，并开展 Context 配对与模型对照。分类、排序、堆叠可作为抓放类别的后续扩展；液体、布料和灵巧手在上述阶段之后单独评估。

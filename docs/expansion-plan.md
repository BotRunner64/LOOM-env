# 拓展方向

## 推进方式

先横向覆盖不同交互类别，再围绕各类典型任务纵向拓展，最后组合成多步任务。一个典型任务跑通后，立即做少量变体验证实现没有依赖单一对象或固定布局，再进入下一类。

任务数量与交互能力分开看：更换对象、容器或目标位置属于**变体**；推移、工具接触、双臂交接等带来新的**交互要求**。参考本地 `sim_projects` 中 RoboDojo、RoboTwin、ManiSkill 和 RLBench 的任务组织，按实际动作与成功判据选择典型案例，不只依据任务名称。

保持动作简单，不扩展复杂朝向控制或绕障。后续新增任务应带来新的物体／场景语义或接触要求；参数扫范围作为回归，不用配置数量衡量任务进展。不以低速度作为任务成功门槛。

## 交互类别

| 类别 | 需要的新能力 | 后续变体 |
| --- | --- | --- |
| 刚体归位与整理 | 真实物体接触适配、可见区域、完整包含与防倾倒 | 布局、干扰物、指定区域选择 |
| 双臂交接 | 两臂时序、接收抓持、递出释放与避碰 | 物体、交接位置、交接方向 |
| 持工具操作 | 工具抓持、作用点与连续接触 | 待扫物数量、分布、目标区域 |
| 关节物体 | 约束运动、状态记录与重放 | 开合方向、目标行程、安装位置 |
| 插销入孔 | 几何对齐、插入与卡住诊断 | 初始偏差、目标位置、配对几何 |
| 多步组合 | 把已跑通的典型任务串起来 | Context 配对与模型对照 |

分类、排序、堆叠可作为抓放类别的后续扩展；液体、布料和灵巧手在上述阶段之后单独评估。

## 场景如何拓展

场景随交互需要逐步增加：通用桌面用于抓放与推移，双臂共享工作区用于交接，工具操作桌面用于扫动，机构／装配工作台分别加载抽屉或插孔夹具。尽量共享桌面和已有资产；对象款式、布局采样、干扰物和可达范围作为场景变体管理。

先固定 Panda 部署；交接使用其双臂。每类完成典型案例及少量对象／布局变化后，再选择代表案例切换本体，不做全部任务、场景和本体的笛卡尔积。

缓存模型不等于可用任务资产，接入遵循[质量门槛](assets.md#质量门槛)。

## 每项如何完成

1. **确认定义与资产。** 查看尺寸、碰撞和功能部位，明确动作过程、成功条件及不可接受的捷径；资产或物理表示的关键选择先讨论。
2. **验收最小案例。** 固定初态跑通完整物理过程，给出视频和测量。例如推移需检查是否被抬起搬运；交接需验证接收抓持后递出释放；插入需排除穿透导致的假成功。
3. **验证少量变体。** 先用少量固定种子检查位置与朝向变化，再增加对象或布局。保留失败，区分初始化、规划、接触执行和判定问题。
4. **整理可复现入口。** 同步配置、采集与重放命令、判据和已知限制；以实际效果和数据完整性验收，不以单元测试或规划成功代替。

实现按任务需要补齐专家、判据和物理状态；发现职责耦合时随案例修正，不把通用架构重构作为拓展前置条件。
